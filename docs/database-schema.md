# Database schema

PostgreSQL 16, managed with Alembic (`backend/alembic/versions/0001` to `0006`). The models are
in `backend/app/models/`. A test (`tests/unit/test_schema_docs.py`) fails if a table or column
below is missing, and another (`tests/integration/test_migrations.py`) fails if the models and
the migrations disagree.

```
users ─┬─< refresh_tokens            (CASCADE: tokens go with their user)
       ├─< audit_logs.actor_id       (no ON DELETE: an audited user cannot be deleted)
       └── referenced by aws_accounts.created_by_id, scans.triggered_by_id,
           findings.status_updated_by_id (SET NULL)

aws_accounts ─┬─< scans ─────────────┐
              ├─< resources ──────┐  │ (resources.last_scan_id, findings.first/last_scan_id:
              └─< findings >──────┘  │  SET NULL, so deleting old scans keeps the rest)
                    └── resource_uuid → resources (CASCADE)
```

Conventions: UUID primary keys generated by the application; timestamps are
`timestamp with time zone`, set from the application clock; flexible, per-type data is JSONB;
enumerations are stored as strings (no PostgreSQL enum types, so adding a value needs no
migration of the type).

## users

Accounts that can sign in. Never deleted, only deactivated.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | primary key |
| `email` | varchar(254) | unique, stored lowercase |
| `password_hash` | varchar(255) | Argon2id hash; the password itself is never stored |
| `role` | varchar(20) | `ADMIN`, `ANALYST` or `VIEWER` |
| `is_active` | boolean | false blocks sign-in and refresh immediately |
| `failed_login_count` | integer | consecutive failures, reset on success |
| `locked_until` | timestamptz | set after 5 failures, for 15 minutes |
| `last_login_at` | timestamptz | |
| `created_at` | timestamptz | |

## refresh_tokens

One row per issued refresh token (sessions). Only a hash is stored.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | primary key |
| `user_id` | uuid | → users, ON DELETE CASCADE, indexed |
| `token_hash` | varchar(64) | SHA-256 of the token, unique |
| `expires_at` | timestamptz | 7 days after issue |
| `revoked_at` | timestamptz | set on rotation, logout, password change or deactivation; a revoked token presented again revokes all the user's sessions |
| `created_at` | timestamptz | |

## aws_accounts

AWS accounts registered for scanning. No credentials are stored.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | primary key |
| `account_id` | varchar(12) | the 12-digit AWS account ID, unique |
| `name` | varchar(100) | |
| `regions` | jsonb | list of region names to scan |
| `role_arn` | varchar(2048) | optional role to assume |
| `created_by_id` | uuid | → users, ON DELETE SET NULL |
| `created_at` | timestamptz | |

## scans

One row per scan; also a snapshot of what that scan saw.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | primary key |
| `aws_account_id` | uuid | → aws_accounts, ON DELETE CASCADE, indexed |
| `status` | varchar(30) | `PENDING`, `RUNNING`, `COMPLETED`, `COMPLETED_WITH_ERRORS`, `FAILED` |
| `triggered_by_id` | uuid | → users, ON DELETE SET NULL |
| `caller_arn` | varchar(2048) | the AWS identity the scan ran as |
| `created_at` | timestamptz | |
| `started_at` | timestamptz | |
| `finished_at` | timestamptz | |
| `resource_count` | integer | resources found by this scan |
| `resource_counts` | jsonb | per resource type |
| `coverage` | jsonb | per service: `SUCCEEDED` / `PARTIAL` / `FAILED`, item count, short error labels |
| `error_summary` | varchar(500) | safe message when the scan failed |
| `finding_count` | integer | findings detected by this scan |
| `finding_counts` | jsonb | per severity |
| `risk_summary` | jsonb | highest risk score and count per priority band (false positives excluded) |
| `rule_results` | jsonb | per rule: `PASSED` / `FAILED` / `INCOMPLETE` / `NOT_APPLICABLE` / `ERROR` and counts |

## resources

The latest known configuration of each AWS resource: one row per resource, updated in place.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | primary key |
| `aws_account_id` | uuid | → aws_accounts, ON DELETE CASCADE |
| `region` | varchar(32) | a region, `global` or `unknown` |
| `resource_type` | varchar(64) | e.g. `AWS::S3::Bucket` |
| `resource_id` | varchar(1024) | AWS identifier (instance ID, group ID, bucket name or ARN) |
| `name` | varchar(1024) | |
| `config` | jsonb | normalized configuration; `null` values mean "could not be read" |
| `first_seen` | timestamptz | |
| `last_seen` | timestamptz | resources deleted in AWS stay; this shows when they were last found |
| `last_scan_id` | uuid | → scans, ON DELETE SET NULL |

Unique: (`aws_account_id`, `region`, `resource_type`, `resource_id`).

## findings

One row per problem (a rule failing on a resource), tracked across scans.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | primary key |
| `aws_account_id` | uuid | → aws_accounts, ON DELETE CASCADE |
| `resource_uuid` | uuid | → resources, ON DELETE CASCADE, indexed |
| `fingerprint` | varchar(64) | SHA-256 of account, rule, resource type, region and resource ID; unique per account |
| `rule_id` | varchar(32) | indexed |
| `title` | varchar(200) | from the rule at the latest detection |
| `category` | varchar(32) | `NETWORK`, `DATA_PROTECTION`, `IDENTITY`, `LOGGING` |
| `severity` | varchar(16) | `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`; indexed |
| `evidence` | jsonb | facts from the collected configuration |
| `risk_score` | integer | 0-100, indexed |
| `risk_breakdown` | jsonb | points and reason per factor, priority, model version |
| `resource_type` | varchar(64) | copied from the resource for filtering |
| `resource_id` | varchar(1024) | copied from the resource |
| `region` | varchar(32) | copied from the resource |
| `status` | varchar(20) | `OPEN`, `ACKNOWLEDGED`, `RESOLVED`, `FALSE_POSITIVE`; indexed |
| `status_note` | varchar(500) | analyst's note, or the scan's reason for an automatic change |
| `status_updated_at` | timestamptz | |
| `status_updated_by_id` | uuid | → users, ON DELETE SET NULL; null with a timestamp means "changed by a scan" |
| `resolved_at` | timestamptz | |
| `first_detected` | timestamptz | |
| `last_detected` | timestamptz | |
| `first_scan_id` | uuid | → scans, ON DELETE SET NULL |
| `last_scan_id` | uuid | → scans, ON DELETE SET NULL |

Unique: (`aws_account_id`, `fingerprint`).

## audit_logs

Append-only record of security-relevant actions. Triggers from migration 0006 reject
UPDATE, DELETE and TRUNCATE.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | primary key |
| `created_at` | timestamptz | indexed |
| `action` | varchar(64) | e.g. `LOGIN_FAILED`, `FINDING_STATUS_CHANGED`; indexed |
| `outcome` | varchar(16) | `SUCCESS` or `FAILURE` |
| `actor_id` | uuid | → users (no ON DELETE action), indexed; null for anonymous or system events |
| `actor_email` | varchar(254) | the actor's email at the time |
| `target_type` | varchar(32) | `USER`, `AWS_ACCOUNT`, `SCAN`, `FINDING`, `ROUTE` |
| `target_id` | varchar(64) | |
| `ip_address` | varchar(45) | client IP (IPv4 or IPv6) |
| `request_id` | varchar(64) | same as the `X-Request-ID` header and the server log |
| `details` | jsonb | safe, event-specific fields; secrets are never stored |

## Migrations

| Revision | Adds |
|---|---|
| 0001 | baseline (empty) |
| 0002 | users, refresh_tokens |
| 0003 | aws_accounts, scans, resources |
| 0004 | findings; finding counts and rule results on scans |
| 0005 | risk score and breakdown on findings; risk summary on scans |
| 0006 | audit_logs and its append-only triggers |

The backend container runs `alembic upgrade head` at start-up (after `check-config`).
